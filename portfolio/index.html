01 · 项目介绍

先是一套完整的协作系统，再让 AI 成为其中的效率增益。

项目的基础能力独立成立：用户与权限、项目和成员、任务与清单、聊天和通知、审计和效能分析。AI 在此基础上参与需求拆解，而不是取代这些业务模块。

项目与任务管理

从项目创建到实际交付

项目、成员、看板、任务、子任务、清单、里程碑和发布记录形成执行链路，任务状态和项目进度可聚合查看。

实时协作与沟通

让信息跟着业务上下文流转

即时消息、在线状态、项目动态与系统通知进入统一协作空间，减少任务推进过程中的信息断层。

过程可追溯

用数据支持追踪和复盘

审计记录、任务生命周期和项目效能视图沉淀过程数据，使需求到交付的每一步都可以回看。

02 · 后端核心亮点

从鉴权、事务到领域模型，后端不是接口的简单堆叠。

关键实现围绕权限边界、多步写入一致性、数据持久化和接口职责展开。这些设计决定系统是否能稳定承接真实协作场景。

认证与访问控制

JWT 实现无状态认证，拦截器统一解析令牌并写入当前用户上下文。

  • ThreadLocal 在请求结束时清理，避免线程池复用导致用户串号。
  • 密码使用 BCrypt 加盐哈希；登录失败计数与锁定时间进入安全策略。
  • 前端路由守卫与后端接口鉴权双层兜底。

事务边界与一致性

多步写入由服务层 @Transactional 统一包裹，确保业务动作具备原子性。

  • AI 应用计划时，任务、子任务、清单与审计记录一并写入。
  • 任何一步失败整体回滚，不遗留半成品数据。
  • 复杂查询通过 MyBatis-Plus 与 XML SQL 组合实现。

领域模型与本地启动

用户、项目、任务、聊天、通知、AI 与审计按领域拆分，不把复杂业务塞进单一模块。

  • 45 张表按业务职责组织，关系服务于协作工作流。
  • TableInitializer 在启动时检查建表、补齐字段并写入种子数据。
  • 新环境只需配置 MySQL 连接即可启动联调。

异常处理与接口边界

统一响应包装和全局异常处理收敛接口返回，Controller 和 Service 各自保持单一职责。

  • @RestControllerAdvice 将业务异常统一转换为标准错误格式。
  • 36 个 Controller 按用户、项目、任务、消息、AI 等领域组织。
  • 前端 API 按后端模块对应拆分，降低跨层耦合。
03 · 实时协作设计

按交互方向选择 SSE 与 WebSocket，而不是让一条通道承担所有事情。

SSE

AI 流式输出与系统通知

AI 对话和计划生成由服务端持续单向输出；通知按用户维护 SseEmitter 集合，向目标用户精确推送事件。

WebSocket

即时消息、在线状态与协作感知

按项目、会话和团队维度订阅长连接，实时同步消息、已读回执、成员在线状态和协同事件。

已读策略

消息位点替代逐条更新

会话成员保存 last_read_message_id。一次已读只更新成员记录，未读数通过消息 ID 位点计算，避免历史消息写放大。

04 · 产品落地

后端能力最终落在真实可用的协作体验里。

即时消息

会话、附件与已读回执通过 WebSocket 同步，消息不再脱离项目协作场景。

项目效能分析

基于任务生命周期计算周期、完成率与趋势，为过程复盘提供数据支持。

05 · AI 辅助能力

AI 是一个受控的业务环节，不是项目的全部。

AI 的价值在于减少需求拆解的重复劳动。系统将上下文注入、结构化计划、人工确认和事务化应用连成闭环，约束模型输出的风险。

提出需求

在项目或任务上下文中输入自然语言需求。

生成计划

通过 SSE 返回任务、子任务、清单与交付物。

人工确认

确认后才触发事务化批量写入与审计记录。

核心设计不是调用模型，而是 Plan → Confirm → Apply：生成计划和写入数据分离，用户始终保有最终决定权。
